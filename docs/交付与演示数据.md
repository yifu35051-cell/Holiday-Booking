# 镜像交付与首次数据准备

当前交付：前端、后端、MySQL 8.4、WireMock 3.13.2-2；邮件使用配置的 DirectMail，不包含 Mailpit。日常启动不构建/下载。发信凭据、工作数据库和制作者的演示密码不随镜像公开交付。

## 接收成员

在交付目录执行：

```powershell
Get-FileHash .\images.tar -Algorithm SHA256
# 与 SHA256SUMS.txt 核对，再导入已打包的运行镜像
docker load --input .\images.tar
if (-not (Test-Path config/deployment.env)) { Copy-Item config/deployment.env.example config/deployment.env }
notepad config/deployment.env
```

首次填写数据库/唯一管理员密码、真实 SMTP 发信地址与专用密码、随机 `WIREMOCK_CALLBACK_SECRET` 和不同的 `TRUSTED_EDGE_SECRET`。SMTP 账号需要成员自己配置或通过团队私密渠道取得，不在包中内置。已有数据库密码不能任意修改，镜像 `APP_VERSION` 与 `images.txt` 保持一致；架构须匹配，例如 linux/amd64。

```powershell
docker compose --env-file config/deployment.env -f config/compose.yaml up -d --no-build --pull never --wait --wait-timeout 300
```

访问 `http://localhost:8088`。第一次启动执行 Flyway 并按配置创建唯一管理员；正常启动没有自动导入演示业务，也不会发送示例邮件。以后可以清空两个 `BOOTSTRAP_ADMIN_*`。容器使用持久卷，`stop` 不删除数据，不要使用 `down -v`。

## 需要模拟数据时执行一次

数据装载器包含在后端镜像里，不需要把制作者的工作库给别人。数据库就绪、已有唯一管理员后，执行专用一次性导入；不要把 `mock/log` 设成正式服务日常模式：

```powershell
docker compose --env-file config/deployment.env -f config/compose.yaml run --rm --no-deps -e SPRING_PROFILES_ACTIVE=local -e PAYMENT_MODE=mock -e EMAIL_MODE=log -e JOBS_ENABLED=false -e DEMO_DATA_ENABLED=true -e DEMO_EXIT_AFTER_SEED=true backend
```

导入原子创建 3 位顾客、2 位员工、4 类/20 间房、日期价/封房、2 个会员方案和预订/资金/邮箱演示场景；原管理员保留。日期按首次导入日计算，完成标记防止重复覆盖。示例地址属于保留测试域，不发送互联网邮件；真实验收需另注册自己控制的邮箱。

开发版等价命令为 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Start-Backend.ps1 -SeedOnly`。开发演示密码在 `.local/demo-accounts.properties`；Docker 中在 `demo-credentials` 卷的 `/app/local/demo-accounts.properties`，由本机运维读取，不能公开发布：

```powershell
docker compose --env-file config/deployment.env -f config/compose.yaml exec backend cat /app/local/demo-accounts.properties
```

这条命令会显示本机演示密码，请勿将输出贴入共享报告。历史导入的 MOCK 交易仍保留原渠道标识；WireMock 模式可以通过同一持久化本地账本核验它们，不把历史交易改写成第三方交易。

## 制作者导出与更新

源码修改后主动构建一次，随后导出；导出脚本从不隐式构建、拉取或启动容器：

```powershell
docker compose --env-file config/deployment.env -f config/compose.yaml -f config/compose.build.yaml build backend frontend
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Export-System.ps1
```

包内有 `images.tar`、版本/摘要、校验和、Compose、`config/wiremock/mappings`、配置示例、启动脚本和本文。新版本使用新的 `APP_VERSION` 标签并在双方配置一致；日常 `up --no-build --pull never` 不会主动包含新源码。

工作数据迁移与“初始化同一套模拟场景”是不同操作。确需迁移工作库时先做私密备份：`python scripts/Database-Maintenance.py backup --mode Docker`，再校验并在隔离 MySQL 演练恢复；不能把含真实会话、私信和 SMTP 凭据的文件混入镜像包。备份/恢复要求见项目源码中的 `docs/design/Current-Design-Baseline.md` 第7节。

跨机器公开服务前配置 HTTPS 与安全 Cookie；当前默认只绑定本机回环。支付仍是本地模拟资金，DirectMail 是真实出站服务。本轮未启动 Docker，镜像交付和首次导入需按项目源码中的整改审查完成实际验收。
