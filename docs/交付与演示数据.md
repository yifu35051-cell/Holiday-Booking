# 生产部署、镜像交付与预设数据

本方案用于项目成员在自己电脑上运行完整系统：Vue 构建产物 + Nginx、Spring Boot、MySQL 8.4、Mailpit，以及 mock 支付。生产/部署版同样启用 mock 支付、Mailpit、邮件任务和三角色邮箱。仅需 Docker Desktop（Linux containers）和 Docker Compose v2；接收镜像的成员不需要安装 Java、Node 或 MySQL。

## 1. 接收镜像包的成员：首次配置，随后一条命令启动

交付目录包含 `images.tar`、`images.txt`、`SHA256SUMS.txt`、`config/compose.yaml`、`config/deployment.env.example`、`scripts/Start-System.ps1` 和本文。先对照 `images.txt` 确认电脑架构与镜像一致，例如 linux/amd64；ARM 电脑优先由同架构机器重新构建，不假定所有电脑都能模拟另一架构。

在交付目录打开 PowerShell：

```powershell
# 校验输出应与SHA256SUMS.txt一致，再导入四个运行镜像。
Get-FileHash .\images.tar -Algorithm SHA256
docker load --input .\images.tar

# 仅首次复制；已有配置不要覆盖。
if (-not (Test-Path config/deployment.env)) { Copy-Item config/deployment.env.example config/deployment.env }
notepad config/deployment.env
```

首次修改三项密码：`MYSQL_ROOT_PASSWORD`、`MYSQL_PASSWORD`、`BOOTSTRAP_ADMIN_PASSWORD`，建议分别使用至少20位随机字符。管理员邮箱可修改为自己的登录邮箱；本地 Mailpit 不要求该邮箱真实存在。密码用单引号包围，不使用模板占位值，不把配置文件发给别人。`APP_VERSION` 保持交付包里的版本。

```powershell
# 接收方常用的一条启动命令：不构建、不拉取，使用刚才导入的镜像。
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Start-System.ps1
```

也可直接使用跨平台命令（Linux/macOS首次复制用 `cp`）：

```sh
docker compose --env-file config/deployment.env -f config/compose.yaml up -d --no-build --pull never --wait --wait-timeout 300
```

打开 **http://localhost:8088**。Mailpit调试页为 **http://localhost:8026**。端口由 `WEB_PORT`、`MAILPIT_WEB_PORT` 调整；默认只绑定127.0.0.1。普通用户在项目内“我的邮箱”收发信，不使用Mailpit调试页。

启动顺序：MySQL及Mailpit健康 → Flyway迁移 → 首次管理员初始化 → 演示数据事务导入 → 后端readiness就绪 → Nginx就绪。启动脚本不会仅凭端口打开就宣布后端可用。

管理员使用自己刚配置的邮箱和密码。第一次成功后可以把两个 `BOOTSTRAP_ADMIN_*` 都清空，后续启动无需初始化；不会重置已有管理员密码，也不会用新的初始化邮箱创建第二个管理员。

## 3. 制作者：首次构建、代码更新、导出

此节仅供有源码的制作者使用；镜像接收方使用第1节。先复制并填写 `config/deployment.env`（已有文件不覆盖），然后在项目根目录执行一次：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Start-System.ps1 -Mode Docker -PrepareImages
```

该操作只准备缺少的镜像，不启动容器。已有MySQL/Mailpit复用同一Docker引擎的本机镜像；仅当指定镜像不存在才拉取。已有项目后端/前端镜像也跳过，仅构建缺少的应用镜像。第一次应用构建可能需要下载Java/Node构建镜像、Maven和npm依赖。`local-v1`只是应用版本，不是包含MySQL/Mailpit的重复安装包。镜像与容器的区别见 [Docker镜像说明](https://docs.docker.com/get-started/docker-concepts/the-basics/what-is-an-image/)。

镜像准备好后，使用第1节的日常启动命令。运行配置无build指令，所有服务使用 `pull_policy: never`；启动命令另外显式指定 `--no-build --pull never`。PowerShell入口先列出复用/缺少的镜像，缺少时在创建容器前停止；原生Compose命令没有此整套预检查。相关行为见 [Docker pull_policy](https://docs.docker.com/reference/compose-file/services/#pull_policy) 与 [Compose up](https://docs.docker.com/reference/cli/docker/compose/up/)。

**源码更新后**显式构建改动的应用服务（`-PrepareImages`不会重建已有镜像），然后执行日常up命令：

```sh
docker compose --env-file config/deployment.env -f config/compose.yaml -f config/compose.build.yaml build backend frontend
```

只改后端或前端时仅填写对应服务；只改运行配置无需构建。同一台电脑日常运行不需要导出/导入。Vue开发热更新与Java开发运行见源码仓库根README中的开发版章节。

需要交给其他成员时，导出已安装的四个镜像：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Export-System.ps1
```

脚本读取 `config/deployment.env` 中的APP_VERSION，输出到 `release/holiday-booking-版本-时间戳/`；不会构建、拉取、启动容器或运行测试。缺少任何镜像会报错。显式 `-Version local-v2` 仅选择已经准备好的该版本镜像，不会生成新版本；再次发布时先修改APP_VERSION并显式构建相应版本。旧 `-SkipBuild` 参数兼容保留，已不必填写。

交付包结构：

```text
images.tar                  四个运行镜像
images.txt                  镜像标签、ID、操作系统/架构
SHA256SUMS.txt               images.tar校验值
README.md                   本指南
config/compose.yaml         只运行镜像
config/deployment.env.example 无真实密码的配置模板
scripts/Start-System.ps1     可选的Windows启动入口
```

导出不包含真实env、`.local`、数据库卷或制作者密码。请把整个目录交给接收方。镜像包用于运行；源码协作仍通过仓库交付。接收更新包时只需校验、`docker load`、将自己配置的APP_VERSION改为交付版本，再执行日常up；保留原数据库密码和数据卷，不复制模板覆盖已有配置。

## 4. 停止、重启、排错与数据保留

以下命令在交付包或项目根目录执行：

```sh
docker compose --env-file config/deployment.env -f config/compose.yaml ps
docker compose --env-file config/deployment.env -f config/compose.yaml logs --tail 100 backend
docker compose --env-file config/deployment.env -f config/compose.yaml stop
docker compose --env-file config/deployment.env -f config/compose.yaml up -d --no-build --pull never --wait --wait-timeout 300
```

`stop`或不带`-v`的`down`保留数据库、Mailpit及演示密码卷。**不要使用 `down -v`**，它会删除这些数据。修改配置文件里的数据库密码不会修改已有MySQL账户密码，已有数据卷必须继续使用原密码，或单独执行正式密码变更。

交付栈项目名为 `holiday-booking-demo`，与开发栈 `holiday-booking` 的卷和容器隔离。切换运行模式时，看不到另一个数据库中新加的记录是正常现象；不是记录丢失。镜像升级使用新版本配置和匹配镜像，保留三个数据卷，再执行up；不要删除演示导入标记来强行重灌数据。

后端不健康时先查日志：常见原因是密码与旧卷不符、首次管理员未配置、演示邮箱冲突或导入失败。前端需等后端readiness后才启动。Docker引擎不可用时先启动Docker Desktop；“Access is denied”属于本机Docker访问权限问题，修改数据库密码不能修复。

## 5. 前端代码可见性与安全边界

已移除Vue DevTools插件及页面浮窗；默认交付只包含压缩后的JS/CSS/HTML，不发布`.vue`、TypeScript源码或source map。构建配置禁止自动注入客户端环境变量；Docker构建上下文使用白名单，真实env和凭据不会进入镜像。Nginx仅提供dist，并拒绝源码/隐藏文件/map路径请求。

**浏览器必须下载前端JavaScript才能运行，无法阻止用户查看这些已交付的代码。**压缩或隐藏调试按钮不能代替权限校验。数据库密码、SMTP凭据、支付私钥只属于后端运行配置；角色、资源归属、金额、库存、CSRF均由后端检查，不能通过修改前端变量获得权限。Session Cookie为HttpOnly，前端不使用localStorage保存密码或授权身份。

Docker对外仅开放回环地址上的前端及Mailpit调试页面；MySQL、SMTP、Java端口只在Compose网络内使用。默认关闭Swagger，添加CSP、防嵌入、MIME及Referrer头，应用容器非root运行。持有Docker管理权限的人能读取容器配置与数据库，这是运维权限，不是浏览器用户权限。

这是本项目的生产/部署运行方式，继续提供mock支付与Mailpit邮箱。mock不发生真实扣款，Mailpit接收SMTP邮件但不自动发往QQ/Gmail等互联网邮箱。若需要跨机器或公网访问，另配置HTTPS、Secure Cookie、入口权限、备份与监控；Mailpit运维页能看到所有捕获邮件，不应直接暴露给普通用户。启用部署模式不要求移除这两个功能。

实现依据：[Vue生产调试开关](https://vuejs.org/api/compile-time-flags.html)、[Vite生产构建](https://vite.dev/guide/build)、[Mailpit健康检查](https://mailpit.axllent.org/docs/integration/healthcheck/)、[非root Nginx镜像](https://github.com/nginx/docker-nginx-unprivileged)。
