# 开发版运行指南

[项目运行总入口](../README.md) · [生产部署与镜像交付](交付与演示数据.md) · [测试入口](testing/README.md)

本文只说明开发版：本机 Java、Vue 热更新，Docker 提供 MySQL 和 Mailpit。命令均在项目根目录执行；不需要本机安装 MySQL。

开发入口必须使用 `Start-System.ps1 -Mode Development`。`config/compose.yaml`和默认Docker模式属于部署版；出现 `holiday-booking-backend:local-v1` 缺失说明正在走部署流程。开发版无需此镜像。两种环境共用本机相同的MySQL/Mailpit镜像，但容器和数据卷独立；不会重复安装镜像。

## 1. 首次准备（只做一次）

安装 JDK 21、Docker Desktop（Linux containers / Compose v2），以及符合 `frontend/package.json` 的 Node。确认 `java -version`、`docker compose version`、`node --version` 可用，JAVA_HOME 与 java 命令一致。

```powershell
if (-not (Test-Path config/development.env)) {
    Copy-Item config/development.env.example config/development.env
}
notepad config/development.env
```

填写 `MYSQL_ROOT_PASSWORD`、`MYSQL_PASSWORD`；已有库继续使用原密码。原根目录 `.env.mysql` 已迁至此处。模板默认开启 mock、SMTP、Mailpit 和定时任务；文件只支持 `KEY=value` 或单引号字面值，不作为脚本执行。

```powershell
# 首次缺少镜像、依赖或JAR时准备；日常启动不会执行这些命令。
docker compose --env-file config/development.env -f config/compose.dev.yaml pull --policy missing mysql mailpit
npm --prefix frontend ci
.\backend\mvnw.cmd -f .\backend\pom.xml -DskipTests package
```

首次准备需要联网下载依赖。后端打包命令跳过测试；业务测试由开发者按测试文档独立执行。

## 2. 日常整体启动 / 分别启动

```powershell
# 整体：Docker数据库和Mailpit → Java已有JAR → Vue热更新
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Start-System.ps1 -Mode Development
```

打开 **http://localhost:5173**。脚本不会安装依赖、编译 Java、构建前端或拉取镜像；准备不全时停止并提示准备命令。原 `-Mode Source` 仍可用，含义相同。日志保存在 `.local/run-时间戳/`；Ctrl+C 停止本次 Java/Vue 子进程，保留容器和数据。

默认按需装载预设数据，需要开发库已有管理员。全新库在文件填写 `BOOTSTRAP_ADMIN_EMAIL` 和 `BOOTSTRAP_ADMIN_PASSWORD`，首次整体启动追加 `-InitializeAdmin`。密码至少12字符、UTF-8不超过72字节；后续不用追加，不重置已有账户。无需预设数据时追加 `-SkipDemoData`。

也可分两个终端分别启动：

```powershell
# 终端一：启动数据库、Mailpit和后端；普通启动不要求管理员凭据。
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Start-Backend.ps1

# 终端二：启动前端
npm --prefix frontend run dev
```

后端单独启动需要首次装载数据时追加 `-SeedDemoData`；新库同时追加 `-InitializeAdmin`。已有 `holiday-mailpit` 容器会被复用，脚本不会为接管容器而删除它；端口不匹配时明确报错。

| 服务 | 默认地址 | 用途 |
| --- | --- | --- |
| Vue | http://localhost:5173 | 三角色门户 |
| Java | http://localhost:8080 | API；健康检查 `/actuator/health` |
| MySQL | 127.0.0.1:3307 | 开发数据库 `holiday_booking` |
| Mailpit SMTP | 127.0.0.1:1025 | 后端投递邮件 |
| Mailpit网页 | http://localhost:8025 | 运维查看捕获邮件，普通用户使用应用内邮箱 |

修改 Java 后，停止后端、显式执行首次准备中的 Maven 打包命令，再启动。Vue 页面修改由 Vite 热更新；依赖锁文件变化时显式执行 `npm --prefix frontend ci`。修改运行配置只需重启，不需要重新打包。

单独运行 Vue 且 Java 不是8080时，把 `frontend/.env.example` 复制为 `frontend/.env.local` 修改 BACKEND_URL。整体启动脚本会自动使用配置中的后端端口。IDE 不会自动读取 `config/development.env`，绕过脚本时需自行设置运行环境。

## 3. 配置检查、数据与停止

```powershell
# 只解析配置、检查工具，不连接数据库、不启动服务。
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Start-Backend.ps1 -CheckOnly

# 向已运行开发库补充预设数据，导入后退出，不占用8080。
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\Start-Backend.ps1 -SeedOnly -UseRunningDatabase

docker compose --env-file config/development.env -f config/compose.dev.yaml ps
docker compose --env-file config/development.env -f config/compose.dev.yaml logs --tail 100 mysql
# 先停止Java/Vue，再停止数据库及Compose管理的Mailpit；保留数据。
docker compose --env-file config/development.env -f config/compose.dev.yaml stop
```

手动创建、未被 Compose 管理的 Mailpit 使用 `docker stop holiday-mailpit` 停止。不要使用 `down -v`；不要修改已执行 Flyway 迁移。预设数据由事务及导入标记防重复，不覆盖已有修改；演示账户密码在 `.local/demo-accounts.properties`，不要提交或发布。

## 4. API协议、登录与测试进程

开发配置 `API_DOCS_ENABLED=true` 时，管理员登录后可查看：

- Swagger：http://localhost:8080/swagger-ui/index.html
- OpenAPI：http://localhost:8080/v3/api-docs

先在 `http://localhost:5173/login/admin` 登录，再在同一浏览器访问上述 localhost 地址。开发代理保留 Session Cookie；Cookie 按主机共享，不按端口隔离。不要一边用 localhost，一边用127.0.0.1；三角色同时测试请使用独立浏览器配置文件。Docker部署版默认关闭这些文档入口。

直接访问受保护接口显示401“请先登录”是正常鉴权。403可能是角色不符或CSRF失效；写请求需先获取 `/api/v1/auth/csrf`，携带会话Cookie和返回的token/headerName，登录后重新获取token。地址栏只能发送GET，不能替代POST登录。Swagger展示协议不代表自动完成写请求的CSRF流程。

`Test-Backend.ps1`运行的是 Java 测试，并不调用已启动的8080。各阶段由 Maven/JVM 启动测试上下文；涉及数据库的测试使用 Testcontainers 独立 MySQL，测试账户与开发库账户不同。纯单元测试无需数据库。日志再次出现 Spring Boot 启动信息不表示开发后端异常重启，也不表示浏览器已经登录。测试输入、预期与实际结果统一见[两阶段测试表](testing/README.md)。

## 5. 常见故障

| 现象 | 处理 |
| --- | --- |
| 缺少镜像/JAR/Vite依赖 | 执行第1节对应准备命令；启动不会自动下载或构建 |
| Docker access denied / 引擎未运行 | 检查当前Windows账户的Docker权限和Docker Desktop状态 |
| MySQL不健康/密码不匹配 | 核对文件与已有数据卷原密码，查看MySQL日志；勿删卷解决 |
| 首次预设数据提示缺少管理员 | 填写管理员配置，首次追加 `-InitializeAdmin`；普通后端启动不强制初始化 |
| 8080或5173已占用 | 正常停止旧服务，或调整配置端口；不要重复启动整套服务 |
| 邮件长期READY | 核对JOBS_ENABLED、SMTP、每日配额及任务状态；正常扫描约60秒 |
| 修改Java后行为未变化 | 日常启动使用已有JAR；先手动打包再重启 |
| 切换部署版后看不到开发记录 | 两套独立数据库；核对当前端口及配置文件 |
