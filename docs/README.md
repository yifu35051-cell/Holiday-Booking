## 角色与功能

登录角色只有 **CUSTOMER（顾客）、STAFF（员工）、ADMIN（管理员）**。匿名访客不是数据库角色，付费会员是权益而非权限角色。员工和管理员的后端 API 已实现，前端页面未实现。注册固定创建 CUSTOMER；员工由管理员通过角色接口设置。

所有写请求需要有效 CSRF；本人资源按登录用户 ID 校验。下表描述当前接口权限，不代表每种权限组合都已完成测试验收。

| 功能 | 匿名 | CUSTOMER | STAFF | ADMIN | 当前实现 |
| --- | --- | --- | --- | --- | --- |
| 查看公开房型、连续可用房、会员方案 | ✓ | ✓ | ✓ | ✓ | 已实现 |
| 注册普通顾客、登录 | ✓ | ✓ | ✓ | ✓ | 注册固定为CUSTOMER，不能指定角色 |
| 本人资料、退出、本人报价/预订/购买单/支付单 | — | ✓ | ✓ | ✓ | 这些接口要求登录，不限制为CUSTOMER；始终只处理本人数据 |
| 查询全部顾客预订及详情 | — | — | ✓ | ✓ | /admin/bookings |
| 查看后台房型（含停用项）、实体房 | — | — | ✓ | ✓ | /admin/room-types、/admin/rooms |
| 新建/更新/停用房型、调整基础价和日期价 | — | — | — | ✓ | /admin/room-types 及 /{id}/rates |
| 增加实体房、启停实体房、封房/解除封房 | — | — | ✓ | ✓ | /admin/rooms 及 /admin/room-blocks |
| 新建/停用会员方案 | — | — | — | ✓ | /admin/membership-plans |
| 修改他人角色 | — | — | — | ✓ | PUT /admin/users/{id}/role；禁止修改自己 |
| 查询支付异常、记录人工复核 | — | — | — | ✓ | /admin/payment-exceptions；复核不执行退款 |
| 查询通知任务、人工重试 | — | — | ✓ | ✓ | /admin/notifications；UNKNOWN需明确确认 |
| 查询操作审计、访问启用的API文档 | — | — | — | ✓ | /admin/audit-logs、/v3/api-docs、/swagger-ui |

暂未实现：取消/改订、退款与对账、找回密码/邮箱验证、真实微信支付、用户/员工/管理员前端页面。支付与邮件渠道配置及真实联调也未完成；日常启动入口仍禁用支付和邮件。

测试表中的角色标签用于筛选业务归属。Service 测试不等于 HTTP 权限测试：ID-005、MA-001/002 覆盖部分员工/管理员授权；房间写入、会员方案维护、通知重试、支付异常复核等接口仍需补齐完整 HTTP 权限组合。当前用例实际结果待执行，不能据接口已实现推断测试通过。

测试账户由 Java 测试自动创建。所有访问数据库的测试使用隔离 Docker MySQL，不使用开发库；纯单元测试不需要数据库。开发库管理员的首次创建方式只在运行指南中说明。
